# Правила подготовки материалов

## Имена файлов

- Только латиница, нижний регистр, дефисы: `videoregistrator-70mai-a810.jpg`.
- Никаких пробелов, кириллицы и заглавных букв — они ломают URL.
- Несколько фото одного товара — суффикс-номер: `...-1.jpg`, `...-2.jpg`.
- Имя файла товара = его `slug` в каталоге. Тогда картинку всегда видно, чья она.

## Изображения

| Назначение | Размер | Формат |
| --- | --- | --- |
| Фото товара | 1200×1200 (квадрат) | `.webp`, запасной `.jpg` |
| Баннер / герой | 1920×1080 | `.webp` |
| Логотип бренда | высота 120, прозрачный фон | `.svg`, иначе `.png` |
| OG-превью | 1200×630 | `.jpg` |
| Иконки | 24×24 в вектор | `.svg` |

- Вставлять только через `next/image` — он сам отдаёт webp и нужный размер.
  Для локальных файлов из `public/` указывать `width`/`height`, иначе поедет вёрстка.
- Тяжёлые оригиналы (> 2 МБ) в `public/` не кладём — им место в `assets/images-raw/`.
- У каждой картинки обязателен осмысленный `alt` на русском.

## Видео

- В `public/video/`: `.mp4` (H.264) + по возможности `.webm`, до ~10 МБ на ролик.
- К каждому ролику — постер-кадр `имя-ролика-poster.jpg`.
- Длинное видео (обзоры, установка) — заливать на хостинг и встраивать, а не класть в репозиторий.

## Тексты и каталог

- Данные каталога — в `content/catalog/`, по файлу на категорию или на товар.
- Обязательные поля товара: `slug`, `name`, `brand`, `category`, `price`, `specs`, `images`, `description`.
- Цены и наличие — одним источником; не дублировать по компонентам.

## Что делать с `inbox/`

Материалы приходят кучей — это нормально. Порядок разбора:
1. Файлы раскладываются по `assets/` (исходники) и `public/` (готовое к показу).
2. Тексты и характеристики переносятся в `content/`.
3. Договорённости и вводные — в `docs/brief.md`.
4. Разобранное из `inbox/` удаляется, чтобы папка отражала только необработанное.

## Рич-контент карточки товара

Дополнительные блоки под конкретный товар набираются в
`content/catalog/products.json`, в поле `rich`. Порядок блоков в списке =
порядок на странице. Нет поля — раздела на карточке просто нет.

Типов пять, и это потолок: у каждого своя работа, любой маркетплейсный
разворот собирается их сочетанием.

### `banner` — кадр и надпись

```json
{
  "type": "banner",
  "title": "Помещается в бардачок, а не в багажник",
  "text": "В девять раз компактнее классического пуско-зарядного.",
  "image": "/images/products/joim-es19-card.webp",
  "flip": true,
  "light": true
}
```

`flip` переставляет кадр налево, `light` делает плашку светлой. Оба поля
необязательные: ими чередуют блоки, чтобы подряд идущие баннеры
не выглядели одинаково.

### `specs` — показания в ряд

```json
{
  "type": "specs",
  "title": "Что показывают приборы",
  "items": [
    { "value": "3 300", "unit": "А", "label": "пусковой ток" }
  ]
}
```

Числа сами отсчитываются при появлении блока. `title` необязателен.

### `columns` — короткие пункты

```json
{
  "type": "columns",
  "title": "Три вещи, которые делают за вас",
  "items": [{ "title": "Проверяет полярность", "text": "MCU-чип…" }]
}
```

Три колонки на десктопе. Вместо иконок — номера: иконки под каждый пункт
рисовать нечем, а случайные из набора выглядят чужими.

### `media` — кадр или ролик во всю ширину

```json
{
  "type": "media",
  "image": "/images/products/joim-es19-klemmy.webp",
  "caption": "Клеммы с модулем защиты — в комплекте"
}
```

Вместо `image` можно дать `video`: `{ "src", "poster", "ratio" }`.

### `text` — просто текст

```json
{
  "type": "text",
  "title": "Почему литий, а не свинец",
  "paragraphs": ["Первый абзац.", "Второй абзац."]
}
```

### После правки

Прогнать `node scripts/typo.mjs` — он расставит неразрывные пробелы
в новых текстах.
